A retention analysis on the real CDNOW transaction log — 23,570 customers, 67,591 orders, Q1 1997 acquisition cohort followed through June 1998.

**The question:** among customers acquired in the same quarter, what about their first purchase predicts whether they come back — and which of those things could the business actually change?

**The answer, in short:** almost nothing predicts it. A model on everything knowable at first purchase reaches a hold-out AUC of 0.576 against a 0.375 base rate. That negative result is what drives the recommendation — because you can't identify *who* will return, the right build is a treatment applied to everyone inside the 90-day window, not a targeting model.

## Findings

| | |
|---|---|
| Never place a second order within 180 days | **62.5%** |
| Median days between 1st and 2nd purchase | **57** |
| Second purchases falling inside 90 days | **~60%** |
| Revenue from the top 20% of customers | **67.8%** |
| Hold-out AUC, first-order features | **0.576** |

The largest apparent lever — get more titles into the first order, a 15pp raw gap across 11,920 customers — was **rejected**. Basket value and title count correlate at 0.75, and the title-count coefficient collapses from +0.22 to +0.04 once value is held constant. Customers who buy three titles come back because they spent more, not because they bought more things. Ranking levers by raw size alone would have picked it.

## The data

CDNOW was an online music retailer (1994–2000, sold to Bertelsmann). This is its real transaction log, the dataset behind Fader, Hardie & Lee's customer-base analysis work. It ships inside the `lifetimes` package, so no download is needed.

It was chosen for its cohort design: every customer was acquired inside one three-month window and observed for 15+ months, so a 180-day repeat window is **fully observed for every customer**. No censoring judgment call, and no chance of scoring a recent customer as churned for being recent.

The data is from 1997. The timing and concentration patterns are structural; 1997 channel tactics are not transferable and none are proposed.

## Running it

```bash
pip install -r analysis/requirements.txt
python analysis/prepare_data.py    # extracts CDNOW -> data/cdnow_transactions.csv
python analysis/run_analysis.py    # -> outputs/metrics.json, outputs/figures/*.svg

npm i pptxgenjs && node analysis/build_deck.js   # -> docs/…executive-deck.pptx
```

Deterministic — same inputs, same numbers. Every figure and every number quoted in the case study is regenerated by that second command.

## Method notes

- **No leakage.** Every model feature is knowable at the moment the first order is placed. Time-to-second-purchase is excluded on purpose — it would predict the target nearly perfectly because it *is* the target restated.
- **Logistic regression over a boosted tree,** deliberately. The output is an argument someone non-technical has to be able to check; coefficients are legible in a way feature importances are not. The cost is a little accuracy.
- **`avg_price` is excluded from the joint model** — it's `value / cds`, a deterministic function of two other predictors, and including all three makes the coefficients meaningless. It's reported on its own instead.
- **Same-day rows are rolled up into single orders.** 2,068 rows collapse. Skipping this would inflate the repeat rate by counting one basket as two purchase decisions.
- **Implementation cost is a judgment, not a computation.** Nothing in a transaction log says what a program costs to build, so effort is recorded explicitly per lever rather than folded silently into the ranking — a reader can disagree with the estimate instead of the arithmetic.
- **Opportunity sizing is deliberately conservative** — a 25% capture rate, because benchmark groups differ from target groups in ways beyond the lever itself. The 3pp lift on the headline recommendation is *assumed, not measured*, and flagged as the thing the holdout exists to prove or kill.
